#### 主要内容
##### 基础篇
+ `git commit`：创建树节点
  + `Git` 仓库中的提交记录保存了目录内所有文件的快照
  + 在你每次进行提交时，它并不会盲目地复制整个目录。条件允许的情况下，它会将当前版本与仓库中的上一个版本进行对比，并**把所有的差异打包到一起作为一个提交记录**。
  + `Git` 还保存了**提交的历史记录**。这也是为什么**大多数提交记录的上面都有 parent 节点的原因** —— 我们会在图示中用箭头来表示这种关系。对于项目组的成员来说，维护提交历史对大家都有好处
+ `git branch <name>`：创建树分支
  + `Git` 的分支也非常轻量。它们只是简单地指向某个提交记录
  + 即使创建再多的分支也不会造成储存或内存上的开销，并且按逻辑分解工作到不同的分支要比维护那些特别臃肿的分支简单多了
  + 只要记住使用分支其实就相当于在说：“我想基于这个提交以及它所有的 parent 提交进行新的工作。”
  + `git checkout <name>`：切换到另一个分支；这时进行提交的修改会并入切换的分支当中
  + 如果你想**创建一个新的分支同时切换到新创建的分支**的话，可以通过 `git checkout -b <your-branch-name>` 来实现
+ 分支与合并：合并分支节点
  + `git merge <name>`：将当前分支合并到目标分支下
  + `git rebase <name>`：实际上就是取出一系列的提交记录，“复制”它们，然后在另外一个地方逐个的放下去（将目标分支内容复制到当前分支后）
<br>

##### 高级篇
+ 在提交树上移动：
  + `HEAD`：
    + `HEAD` 是一个对当前所在分支的符号引用 —— 也就是指向你正在其基础上进行工作的提交记录
    + `HEAD` 总是指向当前分支上最近一次提交记录（最近的一次`commit`）
    + `git checkout <Hash>`：将 `HEAD` 指向对应哈希提交记录
<br>

##### `Push & Pull` —— `Git` 远程仓库
+ `git clone <url-git>`：
  + 在本地创建一个远程仓库的拷贝（并关联）
+ 远程分支：
  + 远程分支反映了远程仓库(在你上次和它通信时)的**状态**
  + 在你切换到远程分支时，自动进入分离 `HEAD` 状态。`Git` 这么做是出于不能直接在这些分支上进行操作的原因, 你必须在别的地方完成你的工作
  + 命名规范：远程分支遵守`<remote name>/<branch name>`的路径，习惯将远程仓库命名为`origin`（简写为`o`）
  + 分离`HEAD`：在进行一次`git commit`之后，`o/main`也不会更新（只更新了`main`），只有在远程仓库中相应分支更新之后才会更新
  + `git fetch`：
    + 从远程仓库下载本地仓库中缺失的提交记录，但并不会更新本地仓库状态，所以本地仓库文件呈现时仍然是原本内容（并没有同步）
    + 更新远程分支指针，指针移动到了最新的提交记录
  + `git pull`：
    + 在`git fetch`中，我们完成了对更新的抓取，此时便可以如同合并本地分支一样，将更新合并到本地
    ```sh
    $ git fetch
    $ git merge o/main
    ```
    + 而`git pull`就完成了上述的过程，将两者结合在一起
  + 模拟团队活动 `git fakeTeamwork`：
    + `git fakeTeamwork`：默认为远程添加一次提交到`main`分支
      + `git fakeTeamwork <name> <n>`：指定添加`n`次提交到`name`分支
  + `git push`：
    + 将本地变更上传到指定的远程仓库，并在远程仓库上合并你的新提交记录
    + 带任何参数时的行为与 Git 的一个名为 `push.default` 的配置有关。它的默认值取决于你正使用的 `Git` 的版本
  + 偏离提交的历史：
    + 当本地代码提交记录与最新的不符， 那么`git push`不会被允许 。实际上它会强制你先合并远程最新的代码，然后才能分享你的工作
    + `rebase`解决方案：用 `git fetch` 更新了本地仓库中的远程分支，然后用 `rebase` 将我们的工作移动到最新的提交记录下（可以使用`git pull --rebase`代替），最后再用 `git push` 推送到远程仓库
    ```sh
    $ git fetch
    $ git rebase o/main
    $ git push
    ```
    + `merge`解决方案：用 git fetch 更新了本地仓库中的远程分支，然后合并了新变更到我们的本地分支（为了包含远程仓库的变更），最后我们用 git push 把工作推送到远程仓库（可以直接使用`git pull; git push`代替）
    ```sh
    $ git fetch
    $ git merge o/main
    $ git push
    ```
